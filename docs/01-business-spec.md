# 业务 Spec：shuweicao 发卡站

> 版本 v1 · 2026-11-19 · 对应技术文档：[02-tech-spec.md](02-tech-spec.md) · 部署文档：[03-deployment-guide.md](03-deployment-guide.md)

## 1. 一句话

做一个面向国内和海外买家的 AI 账号自动发卡站：买家付款后，订单页立即出现账号（卡密），并同时发到邮箱。第一个商品是 **GPT 成品号**。

## 2. 目标

| 目标 | 衡量标准 |
| --- | --- |
| 能卖 | 买家从下单到拿到账号全程自动，无需人工 |
| 收得到钱 | 先上线 USDT 和海外支付，国内支付在备案后接入 |
| 不出事故 | 不超卖、不重复发货、数据每天备份 |
| 可扩展 | 后续能加 Claude、Codex 等商品，以及合伙人 / 分销体系 |

## 3. 上线路线（按顺序）

| 阶段 | 内容 | 前置条件 | 完成标志 |
| --- | --- | --- | --- |
| 0. 技术准备 | 在本机（Mac）把整套系统跑起来，熟悉后台、商品、发货流程 | 无 | 本地能完成一笔测试订单 |
| 1. 部署上线 | 部署到海外服务器，绑定 shuweicao.org | 服务器、Cloudflare、证书 | https://shuweicao.org 能访问 |
| 2. 上架 GPT 成品号 | 商品、价格、卡密导入、售后规则 | 货源、定价 | 商品页可下单 |
| 3. 国外支付 | **USDT**（无需审核，阶段 2 同时就能开）→ **Stripe** | 收款钱包；Stripe 审核通过 | 真实小额订单跑通自动发货 |
| 4. 国内备案 | 新域名 + 国内服务器 + 企业主体备案 | 营业执照 | 拿到 ICP 备案号 |
| 5. 国内支付 | 支付宝官方（电脑网站 / 手机网站支付） | 备案通过、支付宝商户签约 | 支付宝订单跑通 |

> 建议：阶段 2 上架时就同时开 USDT，否则商品上架了也收不了钱。Stripe 审核要时间，**现在就去申请**。

### 3.1 关于备案（重要）

- **shuweicao.org 不能备案**：`.org` 后缀未获工信部批复，阿里云等平台无法为它办 ICP 备案；而且它在 Spaceship（境外注册商）注册，也不满足要求。
- 备案需要：一个已批复后缀的**新域名**（建议 `.com` 或 `.cn`），在**国内注册商**（阿里云 / 腾讯云）注册并用**企业主体实名**；一台**中国内地服务器**（阿里云要求包年包月、累计 3 个月以上）；企业营业执照。
- 个人备案只能做非经营性网站，不能在线交易，所以必须用企业（个体户也可以）主体。
- 风险：管局会看网站实际内容。在国内备案的站点上公开销售 ChatGPT 账号，存在审核不通过或事后被关停的可能。
- 如果备案的唯一目的是接支付宝官方：替代方案是**不备案、国内支付走易支付聚合通道**，代价是资金先到第三方平台，有冻结 / 跑路风险。
- **决策点**：拿到营业执照前，先不投入备案；海外站照常运营。

## 5. 支付

| 渠道 | 面向 | 阶段 | 说明 |
| --- | --- | --- | --- |
| USDT（BEpusdt 自建） | 所有人 | 3（可提前到 2） | 钱直接进自己钱包，无审核、无冻结风险；先开 TRC20 |
| Stripe | 海外信用卡 | 3 | 需要已审核的 Stripe 账户（通常需海外公司主体）；转售账号类业务有被关户风险 |
| 支付宝（XorPay 个人接口） | 国内 | 现在就能开 | **不用备案、不用营业执照**：个人身份证开通（¥100），钱直接进自己支付宝；费率约 1%～1.6%；个人单笔 ≤ ¥1000、单日 ≤ ¥5 万；实名绑定本人，有被风控冻结的风险。详见 [05-alipay-xorpay.md](05-alipay-xorpay.md) |
| 支付宝官方 | 国内 | 5 | 需要营业执照 + 企业 ICP 备案的域名 |
| 易支付（不推荐） | 国内 | — | 资金先进第三方平台（二清），费率 3%～6%，有冻结 / 跑路风险；XorPay 更稳 |

定价规则：后台的手续费字段只做利润统计，不会加到买家付款金额里。如果不同支付方式要不同价格，需要拆成不同商品或二次开发。

## 6. 用户流程

1. 买家进入首页 → 选商品 → 填邮箱（可游客下单）
2. 选支付方式 → 跳到支付页（支付宝 / Stripe 收银台 / USDT 收银台）
3. 支付成功 → 支付平台回调 → 订单标记已付款 → 自动取一个卡密
4. 订单页显示卡密 + 邮件发送卡密
5. 买家可用「订单号 + 邮箱」随时查单
6. 有问题 → 联系售后（TG / 邮箱）→ 按质保规则补发

## 7. 售后与运营

- 售后渠道：Telegram 客服账号 + 售后邮箱（待开通）
- 页面必须写清：质保期、不可用的判定方式、补发 / 退款规则
- 每天检查：库存是否充足、是否有「已付款未发货」订单
- 库存低于阈值显示「库存紧张」，卖完自动缺货，避免收了钱发不出货

## 8. 二期（暂不做）

- 推广返佣、钱包余额、礼品卡、开放 API、分销商 / 分站：**Dujiao-Next 已自带**（见 [04-tiance-teardown.md](04-tiance-teardown.md)），二期先试用自带功能
- 合伙人等级：按累计消费自动升级、等级批发价——自带功能是否覆盖待验证，不够再二次开发
- 引流工具：账号状态检测、Codex 重置倒计时
- 开发票

## 9. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| OpenAI 批量封号 | 售后量激增、亏损 | 写明质保期；库存不要一次备太多；货源多元化 |
| Stripe 判定为禁止行业 | 关户、资金冻结 | 控制占比、及时提现，USDT 为主通道 |
| 信用卡拒付 | 货款两失 | 开 Radar + 3DS，保留发货记录 |
| 备案不通过 / 被关停 | 国内支付接不上 | 备案前确认主体和内容；易支付作为备选 |
| 易支付平台跑路 | 资金损失 | 短周期结算、小额限额 |

> 以上为常见行业情况，不构成法律意见；正式收款前建议找懂跨境支付和备案的人确认。
